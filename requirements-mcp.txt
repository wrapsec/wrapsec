# WrapSec MCP server (opt-in interface adapter). Exposes the wrapsec_scan tool
# over the Model Context Protocol so any MCP-compatible agent can call it.
#
# The server is a thin CLIENT of the WrapSec API via the Python SDK -- it does
# NOT need the full gateway requirements (no fastapi, torch, db drivers, ...).
#
# Install (on the machine that runs the MCP server):
#   pip install -r requirements-mcp.txt
#   pip install -e sdk/python/          # the wrapsec client the adapter wraps
#
# Run (stdio transport -- the default for agent-spawned tool servers):
#   WRAPSEC_API_KEY=wsk_live_... WRAPSEC_BASE_URL=http://localhost:8000 \
#       python -m mcp_server
# Pinned exactly, not floored. The gateway and the adapter build against the
# low-level server API, and the SDK marks parts of that surface provisional --
# the middleware seam carries a note that its signature may change in a 2.x
# MINOR release. An unbounded floor lets an enforcement dependency move under a
# green build, and it already had: the same declaration resolved 2.1.0 locally
# and 2.2.0 in CI. Raising this is a deliberate compatibility change that must
# pass the MCP suites, never an incidental bump.
mcp==2.2.0

# The gateway reads its configuration from a YAML file. Declared here rather
# than inherited: it reaches a full development environment only as a transitive
# dependency of the core application stack, which a host running just the
# gateway does not install.
PyYAML>=6.0,<7.0
